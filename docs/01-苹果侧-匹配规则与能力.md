# 01 苹果侧：匹配规则与能力（一手证据）

可复现命令写在每节末尾。

## 1. 苹果认哪些 Xbox 手柄：`XboxGamepad.dext` 的 IOKitPersonalities

文件：`/System/Library/DriverExtensions/XboxGamepad.dext/Info.plist`
（CFBundleVersion 14.0.24，`OSMinimumDriverKitVersion 27.0`，`IOUserServerName com.apple.gamecontroller.driver.XboxGamepad`）
签名里的 USB 传输授权（entitlement）：`idVendor = 1118 (0x045E)`，`idProductArray = [654, 746, 2816, 2834]`
→ 即 **苹果只为微软自家 VID 的这 4 个 PID 提供 USB 驱动**。第三方 VID 的"Designed for Xbox"手柄也不在这张表里。

| Personality | 匹配层 | 匹配条件（十进制→十六进制） | IOUserClass |
|---|---|---|---|
| Xbox360Device | `IOUSBHostDevice` | bDeviceClass=255, VID=1118, PID=654 (0x028E) | XboxUSBDevice |
| **Xbox360Gamepad** | `IOUSBHostInterface` | class=255, subclass=93 (**0x5D**), protocol=1, VID/PID 同上 | Xbox360Gamepad |
| XboxOneSDevice | `IOUSBHostDevice` | bDeviceClass=255, VID=1118, PID=746 (0x02EA) | XboxUSBDevice |
| **XboxOneSGamepad** | `IOUSBHostInterface` | class=255, subclass=71 (**0x47**), protocol=208 (**0xD0**) | XboxOneSGamepad |
| XboxSeriesXDevice | `IOUSBHostDevice` | bDeviceClass=255, VID=1118, PID=2834 (0x0B12) | XboxUSBDevice |
| XboxSeriesXGamepad | `IOUSBHostInterface` | class=255, subclass=71 (0x47), VID=1118, PID=2834（**未限定 protocol**） | XboxSeriesXGamepad |
| **XboxEliteV2Device** | `IOUSBHostDevice` | bDeviceClass=255, VID=1118, PID=**2816 (0x0B00)** | XboxUSBDevice |
| **XboxEliteV2Gamepad** | `IOUSBHostInterface` | class=255, subclass=71 (0x47), VID=1118, PID=2816 | XboxEliteV2Gamepad |

对本项目直接有用的三点：

1. **Elite V2 与 Series X 的游戏手柄 personality 都没有要求 `bInterfaceProtocol`**（只有 One S 要求 0xD0，360 要求 0x01）。协议字段不写就是"任意"，少一个可踩的坑；但**建议仍然填 0xD0**，以最大化与真机的相似度。
2. **设备级 personality 要求 `bDeviceClass = 0xFF`**，它驱动 `XboxUSBDevice`——GIP 型号需要它来"配置设备/上电"。而 Flydigi5Pico 的 360 设备描述符把 `bDeviceClass` 写成 `0x00`，也能工作（界面级 enough）。做 GIP 时**建议把设备类设成 0xFF**。
3. 匹配是**精确相等**：class/subclass/VID/PID 任一不符就没有任何后续（没有"HID 兜底"）。

复现：
```
plutil -convert xml1 -o - /System/Library/DriverExtensions/XboxGamepad.dext/Info.plist
codesign -d --entitlements - /System/Library/DriverExtensions/XboxGamepad.dext   # 看 USB 授权表
```

## 2. dext 内部类结构（说明"苹果自己当 GIP 主机"）

二进制 `/System/Library/DriverExtensions/XboxGamepad.dext/XboxGamepad`（arm64e，双层 fat）里的类名：
`XboxUSBDevice`（USB 层） / `XboxHIDDevice : IOUserHIDDevice` / `XboxWirelessGamepad`
→ 分型号子类：`Xbox360Gamepad`、`XboxOneSGamepad`、`XboxSeriesXGamepad`、`XboxEliteV2Gamepad`

字符串证据：`IOUSBHostDevice`/`IOUSBHostInterface` 检查、异步 IN/OUT 管道、超时重试（`AsyncReadTimeoutOccurred`）、`USB Device Reset`、`kUSBPreferredConfiguration`，以及 HID 侧属性 `ReportInterval` / `MaxInputReportSize` / `MaxOutputReportSize` / `MaxFeatureReportSize`。
含义：dext 直接驱动手柄的 vendor 接口（GIP），在系统内发布一张 HID 描述符给上层。

复现：`strings -a /System/Library/DriverExtensions/XboxGamepad.dext/XboxGamepad | grep -i -E "xbox|paddle|gip"`

## 3. 拨片（Paddle）在 Apple API 里是一等的

`/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/.../GameController.framework/Headers/GCXboxGamepad.h`：

```objc
// @example The standard Bluetooth-enabled Xbox Wireless Controller does not have paddle buttons
// ... Otherwise, the paddle buttons are directly bound to other inputs on the controller.
@property (nonatomic, readonly, nullable) GCControllerButtonInput *paddleButton1;
@property (nonatomic, readonly, nullable) GCControllerButtonInput *paddleButton2;
@property (nonatomic, readonly, nullable) GCControllerButtonInput *paddleButton3;
@property (nonatomic, readonly, nullable) GCControllerButtonInput *paddleButton4;
@property (nonatomic, readonly, nullable) GCControllerButtonInput *buttonShare;   // macOS 12+
```

`GCInputNames.h` 里另有 `GCInputXboxPaddleOne..Four`（macOS 11 / iOS 14）与 `GCInputLeftPaddle`/`GCInputRightPaddle`（macOS 13）。
框架二进制导出符号（`dyld_info -exports .../GameController.framework/GameController`）里确认存在 `_GCInputXboxPaddleOne..Four`、`_GCXboxGamepad`、`_GCProductCategoryXboxOne`、`_isDeviceXbox`。

**后续实测修订（2026-09-30）**：这些 API 证明 Elite 拨片是框架元素，但并不意味着它是 M1–M4 的唯一原生途径。苹果的 Vader2Pro 设备模型也定义了独立的 `BUTTON_M1..M4`（见 docs/11）。本项目用 Vader2Pro 身份实测触发了 `GCControllerDidConnect`；Generic `0x01/0x05` 身份仅在 IOHID/Chrome 被发现，等待后仍未出现在 `GCController.controllers()`。混合 26 键身份能触发 GC 连接，但新增五键尚未在 GC 元素表中得到独立名称，实体输入仍待回归。

## 4. 游戏侧怎么消费：取决于应用的输入栈

- 原生应用使用 Game Controller 框架时，必须等 `GCController` 发现设备；本机 Generic `0x01/0x05` 固件尚未通过这一关。
- 浏览器可另走 HID 枚举。WebKit 的 [macOS HIDGamepadProvider](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/gamepad/mac/HIDGamepadProvider.mm) 直接匹配 Joystick/Game Pad usage；Chrome 已实际读到本机 Generic 固件的 26 个按钮。因此网页能读输入不证明 GC 框架已采纳。
- SDL、Steam/Input 与游戏可能使用不同后端和映射库，不能从某一条 Xbox 有线处理路径推出所有应用的行为。实际兼容性分别以目标应用的按键、轴、额外键及震动测试验收。

## 5. 为什么不能"软件侧解决"（排除项，避免重复试错）

- macOS **没有 uinput**；IOKit 不提供用户态创建 HID 设备的通用接口（社区项目明确记录 "macOS blocks virtual HID device creation"，只能做事件注入，做不成手柄）。
- 唯一软件路线 = 自己写 **DriverKit dext**（如 `Manolo15v/wolverine-identity` 对 Razer Wolverine 所做：dext 直接讲 GIP，然后在系统内发布"苹果同款" HID 身份）。代价：Xcode + 开发者账号 + 系统扩展授权 + 用户批准，且随系统更新维护。**与"给 USB 小板编程"的目标不符，仅作为对照方案记录。**

## 6. iOS/iPadOS：同源驱动 + 官方支持的有线路径（**D1 修订后暂缓，本节仅存档**）

> 2026-09-28 用户修订目标：**目前仅针对 macOS**。本节内容保留备查，不在当前计划的关键路径上。

**Generic Game Pad 路线的边界**：USB HID 顶层 `Generic Desktop/Game Pad (0x01/0x05)` 说明设备的用途，但并不是 Apple 承诺的 `GCController` 兼容条件。当前 Generic 固件已在 macOS IOHID 和 Chrome Gamepad API 出现；macOS 27.0.1 上 `GCController.supportsHIDDevice` 对它返回 `true`，但等待异步发现后 `GCController.controllers()` 仍为空。Apple 的[控制器发现文档](https://developer.apple.com/documentation/gamecontroller/discovering-game-controllers)说受支持控制器通过 USB 接入 iPhone/iPad 会自动连接，未声明任意自制 HID Game Pad 也受支持。[`GCController.supportsHIDDevice(_:)`](https://developer.apple.com/documentation/gamecontroller/gccontroller/supportshiddevice(_:)) 可在 macOS 查询 HID 支持状态，但不能代替实际连接通知和输入验收；该 API 的官方可用性只列 macOS，不能用作 iOS/iPadOS 的验证步骤。iOS/iPadOS 的 Generic 路线必须接目标设备检查系统控制器列表与 Safari Gamepad API。

网页路径也有平台差别：[WebKit 的 macOS HID 提供者](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/gamepad/mac/HIDGamepadProvider.mm)直接匹配 Joystick/Game Pad usage，而[iOS 家族的提供者选择](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/Gamepad/cocoa/UIGamepadProviderCocoa.mm)使用 `GameControllerGamepadProvider`。这是源码中的路径选择，不是目标 iPhone/iPad 已接纳此固件的实测结论。[iPhone](https://support.apple.com/guide/iphone/connect-a-game-controller-iph9d38dd45f/27/ios/27)和[iPad](https://support.apple.com/guide/ipad/ipad2746a7e9/ipados)用户说明均要求手柄“兼容”。验证须分为 USB 接入、系统“游戏控制器”列表、Safari `navigator.getGamepads()` 输入、额外键、震动和电量；仅第一项成功不足以推断后五项。

**苹果在 iOS 18 / iPadOS 18 / macOS Sequoia 起官方支持"有线 Xbox 手柄"**（USB-C↔USB-C 直连；2024-10 起公开报道）。也就是说：
伪装成 Xbox 手柄接 iPad/iPhone 不是钻空子，而是走苹果**官方支持**的那条路；`XboxGamepad.dext` 的匹配规则对我们一视同仁。

镜像侧证据：iOS 26.1 的 ipsw 还原文件里存在**同名同结构**的
`System/Library/DriverExtensions/XboxGamepad.dext/XboxGamepad.m` 与
`System/Library/HIDPlugins/ServicePlugins/XboxGamepadHIDServicePlugin.plugin/XboxEliteV2GamepadHIDServicePlugin.mm`
（来源：GitHub 上的 ipsw 还原仓库，见 refs/README.md）。

iOS 侧的两条额外约束（macOS 上没有）：
1. **供电**：iPhone 的 USB-C 输出能力弱于 iPad/Mac，而我们要同时给 RP2350 板 + 飞智接收器供电 → 必须实测，必要时用带供电的 hub（见 06 R11）。
2. **验证手段少**：iOS 上看不到 `ioreg`/`hidutil`/系统日志，只能靠支持手柄的 App + 苹果的"控制器"设置界面观察（`GCXboxGamepad.paddleButton*` API 自 iOS 14 起可用）。→ 验收策略：**先在 macOS 上把行为钉死，再用 iPad 做"能不能认"的最终确认**。
