## 2. WebHID 新命令（报告 0x10 / 响应 0x11）

| 命令 | 载荷 | 响应（[0]=status [1]=版本 之后） |
|---|---|---|
| `0x0B GET_DEVICE_INFO` | — | [2]=model [3]=conn [4]=电量 [5]=芯片(lo/hi) [6]=陀螺仪 [7]=能力位 [8..21]=7×fw u16BE [22..41]=SKU 20B [42]=skuValid [43]=exValid |
| `0x0C SET_FIELD` | [1]=fieldId [2..3]=u16LE | [2]=fieldId 回显；白名单 {20,23,25,32,33,34,38}，其余回 status=3 |
| `0x0D SWITCH_SLOT` | [1]=0..3 | [2]=槽位 |
| `0x0E CALIBRATE` | [1]=1 开始 / 0 结束 | [2]=回显 |
| `0x0F GET_FINGERPRINT` | — | [2]=valid [3]=活动槽 [4..11]=槽 CRC16×4 LE [12..13]=全局 CRC16 [14..17]=推送计数 u32 |
| `0x12 SET_NAME` | [1..n]=文本 ≤16B | [2]=字节数 |

`GET_GCFG`(0x08) 的 flags[5] 扩展位：bit2 快速切换 / bit3 中心自校准 / bit4 板载映射 / bit5 XInputHome。

> **0x10 命令字保留**：macOS `IOHIDDeviceSetReport` 会剥离与报告 ID 相同的首字节（实测命令变成第二字节），因此协议层面禁用 0x10 作为命令字；名称命令改用 0x12。Chromium 行为未验证（避开即可）。

## 3. 真机实验结论（2026-10-18）

1. **回报率与 EF 流无关**：`usbReturnRateHz` 1000/500/250/125 各档实测 EF ≈ 735/740/735/711 Hz —— "1000Hz 回报率"是普通模式 USB 侧设置，acquire 高帧率档（~740/s 上限）不受其影响。
2. **0xAF 全局重置**只变 3 字节：`[4] 快速切换 1→0`、`[47] 第三方接管 1→0`（会断 acquire，实验后已恢复）、`[48] 未知字段 1→2`；睡眠/回报率/分辨率等不动。除 `[48]` 外全部可经 0xA0 恢复（37 走 `T` 保底入口）。
3. **A1 推送 = 变化驱动**：空闲 25s 无推送；字段写/切槽/重置后 +1。固件已用其做配置变更自动重读（1.5s 速率限制）。
4. **切换配置槽**（0xA2）0↔1 往返正常，EF 流与 acquire 不受影响；槽 1/2 指纹相同（出厂预置）、槽 3/4 为空。
5. **名称写入可用**：0xA0 field 1（UTF-8）真机 ACK status=0、blob[7..38] 落盘、`[CFG] name=` 显示。
6. **RAM 元数据**（0xA3 子 1）：ram1 len=82 + crc32，可作配置一致性校验。
7. **校准帧**（0x03 子 1/2）：发送成功、无应答（非 ACK 通道）；**完整流程未做真机验证**（按用户要求跳过，页面与控制台入口均已实现）。
8. **拼接帧嫌疑计数器**（`[GLTCH]`）：zero_imu / splice 全 0（此前观察到的爆发为特定窗口；`ef_bad` 稳态 ~0.6% 仍是错位拼接帧）。

## 4. 未覆盖 / 待办

- `0x11 SET_STATUS` 未实测（xinput/dinput/mouse 语义未知、无可靠回滚值）。
- blob `[48]` 未知字段（全局重置 1→2 后无法恢复）。
- 校准完整流程（转杆→结束→生效对比）按用户要求跳过；命令通道验证完成，页面与控制台入口保留。
- 用户槽重置（0xAF 0..3）与出厂重置（129）未实测（会破坏板载预置，只在探针预留）。
- Chromium WebHID 对"命令字 == 报告 ID"的行为未验证（协议已避开 0x10）。
- 名称窗口 16 字节上限（固件截断；官方 blob 窗口 32B）——如需长名再放宽。
