# 14 · 社区项目调研（2026-10）

> 本文为社区调研归档，细节以各项目源码为准（调研时间 2026-10-17/18）。
> 五个项目均为 Vader 5 Pro / 飞智接收器生态，下文按项目整理关键结论，§7 为与本项目的对照待办。

## 1. 调研结论速览

| 项目 | 关键事实 | 对本项目的意义 |
|---|---|---|
| [`xpad-flydigi`](https://github.com/AlexandreFournier/xpad-flydigi) | 接收器 `37d7:2401` 四接口全表；厂商命令会**同步阻塞所有输入端点 ~18ms**；握手/test-mode 命令与我方固件逐字节一致 | 交叉印证输入侧协议与接口布局；约束"扩展流握手必须按需、限速重发" |
| [`openvader`](https://github.com/FilipVajgand/openvader) | Vader 5 Pro 命令全集（心跳/状态/数据流/震动/报告率/睡眠/映射…）+ 禁用命令清单 + 实测属性 | 配置项语义、电池与版本解析、睡眠/报告率设置的一手来源 |

## 2. xpad-flydigi（Linux 内核驱动）

> https://github.com/AlexandreFournier/xpad-flydigi

接收器 `37d7:2401` 四接口（IF0–IF3）：

| 接口 | 描述 | 要点 |
|---|---|---|
| IF0 | XInput（`ff/5d/01`） | 1ms 轮询；标准键 + 震动 |
| IF1 | HID `0xFFA0` | 出厂 2ms 轮询 → 驱动强制改为 1ms；`5a a5` 命令 + 扩展输入 EF 帧 |
| IF2 | HID 鼠标 | — |
| IF3 | HID `0xFFEE` | 标记（另见 §6：手柄自身配置通道） |

关键事实：

- 每条厂商命令会**同步阻塞接收器所有输入端点约 18ms**；因此该驱动只在扩展流停止时按需重发握手（速率受限）。
- 握手序列与 test mode 命令与本项目固件**逐字节一致**：`01 / a1 / 02 / 04` + `5a a5 11 07 ff 01 ff ff ff 15`。

## 3. openvader（macOS 配置 App + `docs/PROTOCOL.md` + 源码）

> https://github.com/FilipVajgand/openvader（含 `docs/PROTOCOL.md`、`Sources/vaderctl`）

命令全集要点：

| 命令 | 功能 | 要点 |
|---|---|---|
| `01` | 心跳 | 回包 `[5]`=型号（`130`=Vader5 Pro）、`[6]`=连接字节、`[11]`=电池（状态 nibble / 电量 nibble）、`[15..28]`=7 组固件版本 BCD（15=主 / 17=接收器 / 19=SI / 21=扳机 / 23=屏幕 / 25=ADC / 27=RF） |
| `02` | 昵称 | — |
| `03` | 硬件状态 | `[9]`=睡眠分钟（0=永不）、`[10]`=报告率、`[11]`=摇杆精度、`[12]`=中心灵敏度；读到 0 表示不可调 |
| `04` | UID | — |
| `10` | 数据流状态 | 含第三方接管位与占用者名 |
| `11` | 设置数据流 | 5 个标志：controller / rawStream / keyboard / mouse / thirdParty，`0xFF`=保持不变；**rawStream=1 即打开 EF 流＝本项目的 test mode** |
| `12` | 震动 | gripL gripR trigL trigR（含扳机马达） |
| `13` | 功能开关 | — |
| `14` | 报告率 | "写"命令存在但 openvader 未实现，载荷格式未知 |
| `15` | 摇杆精度 | — |
| `16` | 灵敏度 | — |
| `17` | 睡眠时间 | 0=永不 |
| `A1/A2` | 配置档 | — |
| `A3–AE` | 映射 / 灯效 / 宏 | 读写 |
| `EF` | 实时输入 | 扩展输入流 |

**禁用命令**（勿发）：`1F`（进 bootloader）/ `AF`（重置全部配置档）/ `FD`（清机）/ `FE`（改身份）。

实测属性：

- EF 流"约 **500 Hz**"（与 tux-invader 一致）。
- 睡眠选项：1 / 5 / 15 / 60 / 180 分钟或永不。
- 精度：8–12 bit 枚举码。
- 灵敏度：Fast / Medium / Slow。

## 4. padctl（vader5pro-remap 演进版）

> https://github.com/BANANASJIM/padctl

- 社区结论：输入**只用 EF（IF1）**，故意不轮询 XInput EP0x81 ——"它没有 IMU/背键/扩展键"。与本项目 EF-only 决策一致。
- 震动走 IF0 的 XInput OUT（8 字节 `00 08 00 LL RR 00 00 00`），无 18ms 代价。
- 输出伪装 Xbox Elite 2（`045e:0b00`），M2/M3 交换对齐物理布局。

## 5. tux-invader（Python 协议实现）

> https://github.com/TJLawInOrbit/tux-invader

- EF 流"约 **500 Hz**（firmware 7.1.4.0）"。
- 命令构造：`5A A5 cmd len payload checksum`，checksum = `sum(bytes[2:]) & 0xFF`。
- 补充位定义：字节 12 bit4/5 = 数字扳机（LT/RT press）；字节 14 bit0 = FN、bit1 = TURBO（约 50ms 脉冲）、bit3 = HOME。
- 声称字节 29 是封包计数器 —— 本机有线实测未观察到单调计数，待接收器侧复核。

## 6. flydigi-dock-tools

> https://github.com/Blank0416/flydigi-dock-tools

- 出厂 **15 分钟睡眠定时器**：休眠时手柄直接离开 USB 总线，被底座/充电唤醒后重枚举 → 15 分钟循环的 surprise-removal；**输入活动会重置计时器**。
- 相关：`0xFFEE` 是手柄自身配置通道（报告 ID 5，64 字节），第三方写入不回应。

## 7. 与本项目对照的待办（现状 2026-10-18）

- 输出侧：本项目输出到 Mac 恒定 **1000 Hz**；输入新鲜度 = EF 帧率（有线/无线实测 **~95–100 Hz**）。

| 待解事项 | 现状 / 线索 | 下一步 |
|---|---|---|
| EF 帧率 vs 社区"~500 Hz"差距 | 本机实测 ~95–100 Hz | 报告率设置 `0x14`（载荷格式未知，见 §3） |
| 睡眠定时器 | 出厂 15 分钟休眠即离总线（§6） | 写 `17`（0=永不） |
| 报告率读取 | 有线手柄实测不回应 `03` | 走接收器 / 蓝牙路径再试 |
| 电池 nibble 比例 | 本机公式 `level*10`；社区两个实现用 `min(level*20, 100)` | 真机定标 |
