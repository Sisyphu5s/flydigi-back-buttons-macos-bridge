# docs/11 — 苹果「设备模型库」：M1–M4 的原生 HID 路径（本轮重大发现）

日期：2026-09-28
状态：**一手证据（本机文件直接读取）**，未做任何系统修改、未接硬件
一句话：**macOS 早就原生支持"背键"这种额外按键**——只要设备匹配苹果模型库里已登记的某个型号。**冒充登记型号比冒充 Xbox Elite 简单一个数量级，且不需要 GIP、不需要认证。**

## 1. 机制：配置包 (Configuration Bundles) + 设备模型

苹果的第三方手柄支持不是硬编码在驱动里，而是由**下载到本机的"资产"(MobileAsset) 驱动**：

```
/System/Library/AssetsV2/com_apple_MobileAsset_GameController_DB1/
└── b1e50bde24de08e8e1e74bce42ca215b6d3c31e9.asset/
    ├── Info.plist                      # CFBundleIdentifier = com.apple.MobileAsset.GameController.DB1
    │                                   # MobileAssetProperties.ConfigurationBundles:
    │                                   #   com.apple.GameController.Configuration.HIDGameControllerMappings
    │                                   #     → GameControllers-Custom.bundle
    │                                   #     → GameControllers-SDL.bundle
    ├── AssetData/
    │   ├── GameControllers-Custom.bundle/   # 苹果手写模型：14 厂商 / 31 型号目录、Devices 表 61 条
    │   │   ├── Info.plist                   # ★ 匹配清单（Devices 数组，见 §2）
    │   │   └── Personalities/<Vendor>/<Model>/*.plist
    │   └── GameControllers-SDL.bundle/      # SDL 映射库派生：148 条，按 v<VID>/p<PID>[/r<rev>] 索引
    │       ├── Info.plist
    │       └── Personalities/v1204/p9233/Flydigi_Vader_2/Default.plist   （例）
    ├── META-INF/
    └── _CodeSignature/
```

消费这些模型的是 `/System/Library/HIDPlugins/ServicePlugins/GenericGamepadHIDServicePlugin.plugin`。
它 import 了一整套 `GCGenericDevice*ExpressionModel`（Add / BitTest / Clamp / Constant / ElementExists / InputElementAttribute / InputElementValue / Interpolate / Multiply / SDLHatFunction）与 `GCGenericDeviceDriverConfigurationServiceServerInterface`，selector 包括 `_onqueue_configureWithModel:error:`、`Applying model: %@`、`_trackedElementsByIdentifier`、`elementWithIdentifier:`、`inputElementWithIdentifier:`、`dispatchKeyboardEventWithValue:forUsage:timestamp:`。

> 注：字符串 `Vader2Pro` / `WithBackButtons` / `MobileUSB` 在磁盘二进制与 dyld 共享缓存里**都不存在**，只出现在资产的文件名里 ⇒ 选择逻辑 = 目录枚举 + IOPropertyMatch，不是硬编码表。

## 2. 匹配清单格式（`GameControllers-Custom.bundle/Info.plist` → `Devices` 数组）

```json
{
  "CompatibilityVersion" : "10.1.36",
  "Identifier" : "com.Flydigi.Vader2Pro.MobileUSB",
  "IOPropertyMatch" : {
      "ProductID"     : 9234,      // 0x2412
      "VendorID"      : 1204,      // 0x04B4（Cypress 的 VID，飞智 HID 模式在用）
      "VersionNumber" : 1280       // 0x0500  → bcdDevice
  },
  "Personalities" : [                                   // ★ 按优先级排列
      "Personalities/Flydigi/Vader2Pro/MobileUSBWithBackButtons.plist",
      "Personalities/Flydigi/Vader2Pro/MobileUSB.plist"
  ]
}
```

`IOPropertyMatch` 的三个键就是 IORegistry 里 HID 设备的属性，来源是 **USB 设备描述符的 `idVendor` / `idProduct` / `bcdDevice`** —— 三者对 RP2350 的 device 侧**完全可控**。

飞智在本机库里的两条登记（原值 / 十进制）：

| Identifier | VID | PID | bcdDevice | Personalities（优先级序） |
|---|---|---|---|---|
| `com.Flydigi.Vader2Pro.MobileUSB` | 0x04B4 (1204) | 0x2412 (9234) | 0x0500 (1280) | `MobileUSBWithBackButtons.plist` → `MobileUSB.plist` |
| `com.Flydigi.Vader2Pro.MobileBluetooth` | 0x07D7 (2007) | 0x40 (64) | 0x0101 (257) | `MobileBluetoothWithBackButtons.plist` → `MobileBluetooth.plist` |

SDL bundle 侧的飞智条目（**注意：不含背键**，可用于区分两种模式）：
`v1204/p9233/Flydigi_Vader_2/Default.plist`（PID 9233，只有标准元素：BUTTON_A/B/X/Y、HOME、MENU、L/R_THUMBSTICK、DIRECTION_PAD、L/R_SHOULDER、L/R_TRIGGER）、`v6421/p64/r1/Flydigi_Vader_2/Default.plist`（VID 6421 = Nordic，无线模式）。

## 3. 模型文件格式（两层）

```
Model
├── Driver                                   # 第一层：HID 元素声明（谓词匹配）
│   ├── Elements : [
│   │     { "Identifier" : "button.a",  "Predicate" : "UsageType == 1 AND UsageTypeIndex == 0"  },
│   │     { "Identifier" : "button.m1", "Predicate" : "UsageType == 1 AND UsageTypeIndex == 14" },
│   │     { "Identifier" : "button.m4", "Predicate" : "UsageType == 1 AND UsageTypeIndex == 17" },
│   │     { "Identifier" : "dpad",      "Predicate" : "UsageType == 3 AND UsageTypeIndex == 0"  } ]
│   └── Input : { "GamepadEventFields" : [ { "ExtendedIndex" : n,
│                   "SourceExpression" : { Type: SDLHatFunction / InputElementValue /
│                                          InputElementAttribute(Attribute: Min|Max) / Constant / … } } ] }
├── PhysicalInput                            # 第二层：GC 物理输入元素
│   └── Elements : [
│         { "Identifier" : "button.m1", "Type" : "Button"|"Dpad", "Analog" : false,
│           "LocalizedNameKey" : "BUTTON_M1",     # ★ 与 GCF 注册表大写标识符一致
│           "SymbolName" : "m1.button.horizontal", "Aliases" : [ "Back Right Button 0" ],
│           "PressedValueSource" : 45,
│           "UpValueSource"/"DownValueSource"/"LeftValueSource"/"RightValueSource" : … } ]
└── ProductCategory : "HID"
```

`LocalizedNameKey` 用的正是 GameControllerFoundation 那张 **158 条元素标识符注册表**里的大写词汇（`BUTTON_M1..M4`、`BUTTON_A`、`BUTTON_LEFT_THUMBSTICK` …）——两条独立证据链在此闭合。

**含背键（BUTTON_M*）的登记型号（grep 一手）**：`Flydigi/Vader2Pro/{MobileUSB,MobileBluetooth}WithBackButtons.plist`、`8BitDo/{Pro2,Pro3,Ultimate2WirelessController,Ultimate3ModeForXbox,UltimateMGX}/WithBackButtons.plist`、`8BitDo/Ultimate3E/Default.plist`、`Corsair/scuff-omega/Default.plist`、`SteelSeries/Vizier/Default.plist`、`Backbone/backboneone/*`（4 个）。

## 4. 目标布局 —— 固件按此做（一手完整导出）

`MobileUSBWithBackButtons.plist` 两层元素已完整导出（22 条 Driver / 20 条 PhysicalInput）。下表 `1/N` 表示谓词 `UsageType == 1 AND UsageTypeIndex == N`：

| GC 元素 (`LocalizedNameKey`) | 谓词 | 别名 / 备注 |
|---|---|---|
| `BUTTON_A` / `BUTTON_B` / `BUTTON_X` / `BUTTON_Y` | `1/0` `1/1` `1/3` `1/4` | Button A/B/X/Y |
| `LEFT_SHOULDER` / `RIGHT_SHOULDER` | `1/6` `1/7` | |
| `BUTTON_MENU`(:start) / `BUTTON_OPTIONS`(:select) / `BUTTON_HOME` | `1/11` `1/10` `1/19` | Button Menu / Button Options / Button Home |
| `BUTTON_LEFT_THUMBSTICK` / `BUTTON_RIGHT_THUMBSTICK` | `1/12` `1/13` | |
| **`BUTTON_M1` / `BUTTON_M2` / `BUTTON_M3` / `BUTTON_M4`** | **`1/14` `1/15` `1/16` `1/17`** | **Back Right Button 0 / Back Left Button 0 / Back Right Button 1 / Back Left Button 1** |
| `LEFT_TRIGGER`(:lt) / `RIGHT_TRIGGER`(:rt) | `2/5` `2/4` | `Analog : true`（扳机是带模拟值的 Button） |
| `LEFT_THUMBSTICK`(:thumbstick.left) / `RIGHT_THUMBSTICK` | `2/0..1` / `2/2..3` | Type = Dpad，值源 Up/Down/Left/Right |
| `DIRECTION_PAD`(:dpad) | `3/0` | 用 `SDLHatFunction` + `Mask` 拆方向 |

**设备端要摆的 HID 布局（经典 DInput 形）**：
- 轴 `UsageType 2`：index 0..5 = **X, Y, Z, Rx, Ry, Rz** → 左摇杆 X/Y、右摇杆 Z/Rx、**RT = Ry、LT = Rz**
- hat `UsageType 3 / 0` = Generic Desktop **Hat switch (0x39)** = dpad
- 按钮 `UsageType 1`：**连续 20 位（Button page usage 1..20）**，其中 **M1..M4 落在 Button 15/16/17/18**；模型未引用的 Button 3/6/9/10/19 留给真手柄的杂项键（我们声明或留空都可以，模型不引用）

**语义已定案（2026-09-28 晚，普查 202 个 personality 文件）**：`UsageType` 是**元素类别** `{1=Button, 2=Analog, 3=Hat}`（不是 usage page）；`UsageTypeIndex` 是**该类元素在描述符中的 0-based 位置**（位置敏感）。决定性反证：`v121/p6214/r256` 上出现 `2/12 lefttrigger`、`2/16 righttrigger`、`2/20 rightx`（按 usage−0x30 解释等价 usage 0x3C/0x40/0x44，不是任何轴）；`RotorRiot` 上出现 `3/1 dpad.y`（同设备两个 hat 类元素，而 Hat switch usage 只有一个）。

⇒ **硬约束：按钮/轴/hat 的数量与顺序即语义**，固件不得插入多余同类元素，否则后续位置全部错位。按本节的连续 20 按钮 + 6 轴 + 1 hat 布局，M1..M4 稳定落在 Button 15..18（bit 70..73）。
**该布局已由 `firmware/verify.sh` 主机验证通过（描述符 97 字节，输入报文 10 字节、Output 报文 8 字节 / 模型 22 条谓词全中 / C 与 Python 逐字节一致）——详见 `firmware/report-verification.md`。**

⇒ **固件要做的 output 侧 = 一个「VID 0x04B4 / PID 0x2412 / bcdDevice 0x0500、6 轴 + hat + 20 按钮」的普通 HID 手柄**。不需要 GIP、不需要认证。

## 5. 本项目的路线改变（结论）

**原路线（GIP 冒充 Xbox Elite）**：需要 GIP 主机握手 + 能力位图 + 认证规避，且本机反汇编已证明苹果的 GIP 链路**没有拨片传输者**（docs/10 §6.5）→ 拿不到 `paddleButton1..4`。

**新路线（冒充苹果登记型号）**：
```
RP2350 device 侧声明：idVendor=0x04B4, idProduct=0x2412, bcdDevice=0x0500
 + HID 报告描述符：6 轴 + hat + 连续 20 按钮（M1..M4 = Button 15..18）
 ⇒ macOS 套用 Apple 自己的 Vader2Pro/MobileUSB 模型
 ⇒ 系统里出现 4 个独立元素，标识符 BUTTON_M1..M4
 ⇒ 输入侧只需把飞智 Vader 5 Pro 的 M1..M4 转发到那 4 个按钮位
```

收益：**不需要 GIP 协议、不需要认证、不需要逆向苹果的 GIP 主机行为、不需要冒充 Elite**；输出侧退回"普通 HID 手柄"，实现难度与风险大幅下降。

代价/边界（必须明说）：
1. 这些元素属于 **HID 类别（`ProductCategory = "HID"`）**，**不是** `GCXboxGamepad.paddleButton1..4`。软件要读到它们需遍历 `GCPhysicalInputProfile.elements`（按 identifier），而不是读 Xbox 专属属性。
2. 仍未从代码确证的项见 §6；按钮部分已被 §4 的"对齐布局"消解。

## 8. 真机验证结果（2026-09-29，Stage-2 固件实测）

### 8.1 现场
板子（Waveshare RP2350-USB-A）已刷 **`RP2350 Pad Bridge (stage 2)`**：
- **A 口 = PIO-USB host（GP12/13）** ← 飞智 Vader 5 Pro 2.4G 接收器；接收器接口 `FFA0/0001`，已收 **335 个 32 字节报文**，板子已解出摇杆/扳机/dpad/btn/ext/ext2。
- **C 口 = USB device**：冒充 Xbox Elite v2 + **设备侧 GIP** + CDC 控制台（命令 `i`=info、`r`=raw、`d`=demo、`n`=neutral、`l`=gip-log、`g`=gip-rehandshake、`u`=usb-reconnect、`b`=bootsel、`x/z`=inject）。
- macOS 侧：`com.apple.gamecontroller.driver.XboxGamepad` 接管（接口 0 用户类 **`XboxEliteV2Gamepad`**）；GIP 日志显示完整流程：厂商接口打开 → 主机 `POWER_MODE` → 我方 `ANNOUNCE(0x02)` → `identify(0x04)` 分块 58+46 字节（`class=Windows.Xbox.Input.Gamepad`）→ 主机开始要数据。
- GC 层：`GCXboxGamepad`，34 个元素。

### 8.2 实测结论
1. **Elite/GIP 路线拿不到背键（已实测证实）**：`paddleButton1..4` 全为 nil，元素表里没有任何背键元素。与反汇编结论一致（Apple 二进制 0 处 paddle 解码）⇒ **§5 的路线改写不是猜测，是实测结论。**
2. **端到端标准输入已通**：固件 `d`(demo) 模式下，Mac 的 GameController 框架实时收到 A/B/X/Y 轮换、方向键、双摇杆、双扳机变化（34 元素全部可读）。
3. **输入侧已通**：接收器 → 板子这一段已在工作（32 字节报文被解析成 LX/LY/RX/RY/LT/RT/dpad/btn/ext/ext2）。
4. **背键实体对应仍待回归**：协议位定义已写入 `flydigi_rx.h`，但当时未按键的接收器报文**完全静态**（60 秒内 114 个样本仅同一帧 `5A A5 EF 09 00 08 00 …`），尚不能据此证明每个实体 M 键与定义逐一对应。`firmware/probe/capture_mkeys.py` 现按当前固件的 `x` 控制台命令采 EF 原始帧并记录按键位变化；`r` 会重发接收器初始化命令，不再用于被动抓取。

### 8.3 subagent 补充的一手事实（2026-09-29）
- **`Driver.Elements` 谓词有两种形态**：`UsageType == N AND UsageTypeIndex == M`（多数型号）与 **`UsagePage == 9 AND Usage == X`**（Corsair / SteelSeries / PowerA / GAMR / Tech4Home）。我们的描述符在两种形态下都命中（Button page = 0x09）。
- Flydigi **蓝牙版** m1..m4 的 index 是 **22/20/21/17**（USB 版 14/15/16/17）——同一厂商、同一逻辑键、不同传输/描述符规模 → **再次印证"类内序位"而非 usage 数值**。
- **候选身份门槛对比**：`com.corsair.scuff-omega` 最宽松（`IOPropertyMatch` 无 `bcdDevice`、无 `Transport`，且有 11 个额外键）；`com.8BitDo.Pro2.*` 带 `IOPropertyMatchingPredicate` 描述符门限（要求 elements 含 usage(0x09,0x03) 与 (0x09,0x06)）；**Vader2Pro 需精确三元组（含 bcdDevice=0x0500），我们完全可控 ⇒ 仍首选**（4 键正好够用，且是纯 USB HID、无蓝牙/触摸板包袱）。
- **社区先例（Linux，不能照搬）**：`padctl` 的 `flydigi/vader5.toml` 在 Linux 上冒充 Xbox Elite Series 2 并把 M1–M4 映射到 `BTN_TRIGGER_HAPPY5-8`（xpad 惯例，Steam 按 paddle 槽位读）。**macOS 行为相反**：GIP 链路不产出 paddle ⇒ 同一身份在两端结论不同，别把 Linux 经验搬过来。
- 后台任务 B（插件如何选模型/`_onqueue_configureWithModel:` 调用链）**超时未产出完整报告**，该链路细节仍以本文 §1/§3 为准。
